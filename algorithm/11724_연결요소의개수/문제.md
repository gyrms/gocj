# 백준 11724 — 연결 요소의 개수

🔗 https://www.acmicpc.net/problem/11724
`Silver 2` · `DFS/BFS` · 그래프형

---

## 문제

방향 없는 그래프가 주어졌을 때, **연결 요소(Connected Component)의 개수**를 구하시오.

**연결 요소** = 서로 이어져 있는 정점들의 묶음(덩어리).

```
   1 ─── 2          3 ─── 4
    \   /                 │
      5                   6

   덩어리 ①            덩어리 ②
   {1, 2, 5}          {3, 4, 6}

   → 답: 2
```

---

## 입력

```
첫째 줄   정점 개수 N, 간선 개수 M     ← ⚠️ 한 줄에 둘 다!
이후 M줄  간선의 양 끝점 u, v
```

- 1 ≤ N ≤ 1,000
- 0 ≤ M ≤ N×(N-1)/2
- u ≠ v, 같은 간선은 한 번만 주어짐

## 출력

연결 요소의 개수.

---

## 예제

**예제 1** (`input.txt`)
```
6 5
1 2
2 5
5 1
3 4
4 6
```
출력 → `2`

**예제 2** (`input2.txt`)
```
6 8
1 2
2 5
5 1
3 4
4 6
5 4
2 4
2 3
```
출력 → `1`
(간선이 늘어나 두 덩어리가 이어짐)

## 2606과 무엇이 다른가

| | 2606 바이러스 | **11724 (이 문제)** |
|---|---|---|
| 묻는 것 | 1번과 이어진 게 **몇 개** | **덩어리가 몇 개** |
| 시작점 | **1번 하나만** | **모든 정점을 시도** |
| `dfs()` 함수 | — | **완전히 동일. 손댈 필요 없음** |
| 입력 첫 줄 | `N` 한 줄, `M` 한 줄 | **`N M` 한 줄에 같이** |

## 풀이 힌트

### 핵심 아이디어

> **`dfs(i)` 한 번 = 덩어리 하나를 통째로 방문**
>
> 그러니까 **`dfs`를 몇 번 불렀는지 세면 그게 곧 덩어리 개수다.**

2606은 "1번 덩어리만" 보면 되니 한 번만 불렀고,
이 문제는 "전부" 봐야 하니 **아직 안 가본 정점마다** 부른다.

### 바깥 for문이 추가된다

```java
int count = 0;
for (int i = 1; i <= n; i++) {
    if (!visited[i]) {   // 아직 아무도 닿지 않은 정점이면
        dfs(i);          // 여기서 출발해 덩어리 하나를 전부 훑고
        count++;         // 덩어리 +1
    }
}
```

예제 1로 따라가보면:
```
i=1 → 방문 안 됨 → dfs(1) 실행 → 1,2,5 전부 방문됨 → count=1
i=2 → 이미 방문됨 → 건너뜀
i=3 → 방문 안 됨 → dfs(3) 실행 → 3,4,6 전부 방문됨 → count=2
i=4 → 이미 방문됨 → 건너뜀
i=5 → 이미 방문됨 → 건너뜀
i=6 → 이미 방문됨 → 건너뜀
→ 답 2
```

### 자주 하는 실수

1. **입력 첫 줄을 두 줄로 읽음** → 2606 습관. 여기선 `StringTokenizer` 로 쪼개야 한다
2. `graph[i] = new ArrayList<>()` for문 누락 → NPE
3. 양방향 `add` 누락 → 덩어리가 쪼개져 답이 커짐
4. 바깥 for문 없이 `dfs(1)` 만 호출 → 항상 1이 나옴
